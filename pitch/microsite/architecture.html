Section 07, in detail

Nothing is recorded, then deleted. Nothing is recorded.

The private-by-default promise is enforced architecturally, not by a retention policy. That distinction matters: a retention policy is a promise about what happens to a record that exists; this is about there never being a record to begin with.

What's stored vs. what never is

The only things that survive a session are the outcome and, if triggered, the category. Never the words that produced it.

Stored
  • Date, participants, session type
  • Resolved: yes / no, per person
  • Reconfirmed: yes / no, per person
  • Which floor category fired, if any, and its severity level (category and level only, never the words that produced it)
Never stored
  • Session transcript or audio
  • Pre-session summary text
  • Anything said in private processing conversations

Where it actually dies

Everything operates on ephemeral in-memory streams. The transcript window exists only long enough to feed the classifier and the facilitator's own context, then is discarded.

mic audio→ streaming STT→ rolling transcript window→ fast classifier + facilitator LLM→ discarded, not written to disk
The one narrow exception

The tamper-evident trigger record: category and timestamp only, cryptographically signed or append-only logged, not a row in an ordinary database Mend's own engineers could edit. It's deliberately built to function as evidence in itself, so HR can treat "this met harassment, level 3" as established while conducting its own independent investigation.

Considered and rejected

Recording sessions and auto-deleting them once both parties confirmed resolution, specifically so they couldn't be subpoenaed later. Rejected: that's spoliation of evidence, not a privacy feature. Never creating the record in the first place sidesteps this entirely: nothing to subpoena because nothing was made.

Mid-session escalation, three tiers

Not every tier needs a floor trigger. Only the narrowest one needs hard real-time gating.

Rising tension, not a violation

The facilitator can pause and check in privately, no floor trigger required. The person decides whether to continue or end it, not the bot.

Serious, not acute

The bot doesn't announce it live. It steers to the same routine-sounding close every session gets, then tells each person individually, once apart, what's being escalated and why.

Active, escalating, imminent

A short delay, the broadcast-delay pattern, sits between what's said and what's received. Content crossing this bar is cut before delivery, not interrupted after the fact.

Proving it, not just claiming it

"Trust us, we don't log it" is a weak claim on its own. There's a real hierarchy of ways to back it up.

01
Table stakes
A SOC 2 Type II or ISO 27001 audit: an independent auditor reviewing the real architecture and logging config over months, attesting there's no persistence path for conversation content. Plus published architecture diagrams showing what's ephemeral vs. actually stored, and a contractual warranty with audit rights and real penalties, ideally extended to employees themselves as third-party beneficiaries, not just the employer.
02
Verifiable, not just attested
Third-party code review or code escrow, under NDA, confirming there's no code path that writes conversation content anywhere durable: the implementation, not a description of it. An open "prove it leaked" bug bounty adds an adversarial check on top.
03
Strongest available today
Confidential computing: live session processing inside a hardware-isolated Trusted Execution Environment, so even Mend's own engineers can't access memory contents during processing, with cryptographic attestation that the enclave is running exactly the audited code. Not speculative: Apple's Private Cloud Compute ships the same pattern today. The same mechanism covers the trigger record: a signed, append-only transparency log, provable and tamper-evident without ever logging the words behind it.
Realistic path

Table stakes is what closes early deals. Confidential computing is a genuine, achievable differentiator, not vaporware: a roadmap item once "provably private" becomes central to the pitch rather than a day-one requirement.
